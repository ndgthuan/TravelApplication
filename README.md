# TravelApplication

Flutter app for managing trips: create itineraries, invite members, collaborate in real time, view routes on a map, check-in, and use utilities (weather / currency / translation / world clock). The repo also includes optional Python backends used by some features (AI Travel Agent + explore data scraping).

## What’s in this repo

- **Flutter app** (this folder)
  - Source: `lib/`
  - Firebase config: `firebase.json`, `lib/firebase_options.dart` (and your local `android/app/google-services.json`)
  - Firestore rules: `firestore.rules`
- **Backend tools**: `backend/`
  - **AI Travel Agent API**: `backend/travel_agent/` (FastAPI, Gemini-powered plan generation/editing; used by the in-app Travel Agent chat)
  - **Explore data scraping**: `backend/explore_scrapper/` (Apify-powered Google Maps scraping to build `lib/assets/data/explore_destinations.json`)
  - **Image translate server**: `backend/image_translate/translate_server.py` (Flask + Playwright; runs a local service to translate images via Google Translate UI)

## Tech stack

- **Flutter/Dart**: `provider`, `get_it`, `easy_localization`, `flutter_dotenv`, `firebase_*`
- **Firebase**: Authentication + Firestore
- **Maps/Routing**: Mapbox + OpenStreetMap (`flutter_map`), optional OpenRouteService road routing
- **Python backends** (optional): FastAPI/Uvicorn, Flask, Playwright

## Requirements

- **Flutter**: SDK \(Dart `sdk: ^3.9.2`\)
- **Firebase project**: Auth + Firestore
- **Optional external keys** (only needed if you use the feature):
  - **OpenRouteService**: nicer road routes between itinerary points
  - **fxratesapi** token: historical currency chart data
  - **EmailJS** keys: “Contact support” screen
  - **Gemini / travel agent keys**: for the AI Travel Agent backend
  - **Apify token**: for `backend/explore_scrapper/`

## Quickstart (Flutter app)

### 1) Install dependencies

```bash
cd TravelApplication
flutter pub get
```

### 2) Create `.env`

The app loads `.env` at startup (`lib/main.dart`), and `pubspec.yaml` declares `.env` as an asset.

```bash
cd TravelApplication
copy .env.example .env
```

Fill keys as needed:

| Key | Used by | Required? | Notes |
|---|---|---:|---|
| `OPENROUTE_SERVICE_API_KEY` | road routing for map polylines | Optional | If missing, app draws straight line segments as a fallback |
| `CURRENCY_TOKEN` | historical currency rates chart | Optional | Used with `fxratesapi` time-series endpoint; latest rates can still load without token |
| `SERVICE_ID` `TEMPLATE_ID` `PUBLIC_KEY` `PRIVATE_KEY` | contact support (EmailJS) | Optional | If missing, sending support email will fail |

### 3) Firebase setup

This project is already wired for Firebase via FlutterFire config files:

- `firebase.json` points FlutterFire to the Firebase project and the Android `google-services.json` output.
- `lib/firebase_options.dart` is generated by FlutterFire CLI.

To use your own Firebase project:

- Create a Firebase project in the [Firebase Console](https://console.firebase.google.com)
- Enable **Authentication** providers you want (Email/Password, Google, Facebook, …)
- Create **Firestore Database**
- Run FlutterFire CLI (recommended) to regenerate config:
  - `flutterfire configure`
- Add the Android config file at `android/app/google-services.json` (generated/downloaded from Firebase Console or via FlutterFire)
- Publish Firestore security rules from `firestore.rules` in Firebase Console → Firestore → Rules

### 4) Run

```bash
flutter run
```

## App architecture (high level)

- **Entry point**: `lib/main.dart`
  - loads `.env`
  - initializes Firebase
  - initializes localization (8 locales)
  - registers dependencies via `core/di/injection.dart`
  - sets `home` based on `FirebaseAuth.instance.currentUser`
- **State management**
  - `provider` for ViewModels (`ChangeNotifier`)
  - `get_it` for dependency injection
- **Feature modules**: `lib/features/*`
  - `auth`, `account`, `home`, `explore`, `plan`, `notification`, `utilities`, `support`, `onboarding`
- **Domain/Data split**
  - Interfaces: `lib/domain/**`
  - Implementations: `lib/data/**`
- **Shared services**
  - Routing: `lib/shared/services/route_service.dart` + `open_route_service.dart`
  - AI travel agent client: `lib/shared/services/travel_agent_service.dart`

## Firestore data model (from `firestore.rules`)

Top-level collections and key subcollections:

- `users/{userId}`
  - `saved_destinations/{docId}`: user’s saved places
  - `plan_created/{planId}`: plans owned by the user
    - `activity_created/{activityId}`: activities inside a plan
  - `plan_shared/{planId}`: references to plans shared with this user
- `plan_invites/{inviteId}`: invitations
  - readable by invitee, creatable by inviter, updatable by invitee
- `plan_presence/{roomId}/viewers/{viewerId}`: presence for “who is viewing this plan”

## Optional backend: AI Travel Agent (FastAPI)

The Flutter app calls a local backend at **`http://localhost:5001`** via `lib/shared/services/travel_agent_service.dart`.

### Endpoints (backend)

Implemented in `backend/travel_agent/main.py`:

- `POST /edit-plan`: modify an existing plan based on a command and current plan JSON
- `POST /generate-trip-plan`: generate a brand-new plan from a prompt
- `GET /search-flights`: flight search via Amadeus (test API)
- `POST /invoke`: placeholder chat endpoint (non-plan edits)

### Run the server

```powershell
cd c:\Studybase\TravelApplication\backend\travel_agent
uvicorn main:api --port 5001
```

### Android emulator: connect to the server

From another terminal:

```powershell
adb reverse tcp:5001 tcp:5001
```

Then `http://localhost:5001` inside the emulator will reach your host machine.

### Travel Agent `.env` (backend)

`backend/travel_agent/main.py` loads `.env` from:

- `backend/travel_agent/.env` (preferred)
- `backend/.env` (fallback)

Keys documented in `backend/travel_agent/README_ENV.md` (Gemini, Tavily, Geoapify, OpenWeather, RapidAPI hotels, Amadeus).

## Optional backend: Image translate server (Flask + Playwright)

File: `backend/image_translate/translate_server.py`

- Runs a local Flask server on **port 5000**
- Uses Playwright to automate Google Translate “Images” mode
- Endpoint: `POST /translate-image` with `{ image: <base64>, target_lang: "vi" }`

Note: This server launches a real Chrome window (headful) and keeps a persistent profile folder at `backend/image_translate/playwright_chrome_profile/`.

## Optional tool: Explore dataset scraper (Apify)

Folder: `backend/explore_scrapper/`

Primary script: `backend/explore_scrapper/explore_scrapper.py`

- Uses Apify’s Google Maps Scraper actor
- Writes JSON to `lib/assets/data/explore_destinations.json` by default
- Loads `.env` from the Flutter project root (`TravelApplication/.env`) and expects `APIFY_TOKEN` (or pass `--token`)

Example:

```powershell
cd c:\Studybase\TravelApplication\backend\explore_scrapper
python .\explore_scrapper.py -q "cafe in Da Lat" -n 50 -a
```

## Troubleshooting

### Firebase errors at startup

- Ensure `android/app/google-services.json` exists locally and matches the package name you configured in Firebase.
- If you regenerated Firebase config, make sure `lib/firebase_options.dart` matches your project.

### `.env` not found / keys are null

- Ensure `.env` exists at the project root (`TravelApplication/.env`)
- Ensure `pubspec.yaml` includes `.env` under `flutter.assets` (it does)
- Restart the app after changing `.env`

### Travel Agent chat says it can’t connect

- Start the backend: `uvicorn main:api --port 5001`
- If using an Android emulator: run `adb reverse tcp:5001 tcp:5001`

### OpenRouteService routing not working

- Verify `OPENROUTE_SERVICE_API_KEY` is present
- If missing/invalid, routing will gracefully fall back to straight lines between points
